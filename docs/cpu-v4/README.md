# CPU v4 — 初期配置・相手の立場・発展カード（2026-09-10）

ユーザーの追加要件を受け、v3 の手順探索に以下を追加した候補。
最終比較・戦術・公平性・WebAssemblyの検証を通過し、ローカルの最高難易度「さいきょう」に採用した。

## 初期配置

`setup_search.rs` は各合法配置からスネーク順の配置終了までをシミュレーションする。
相手を、従来の産出重視・建設速度と港重視・資源の種類重視の3通りの方策で動かす。
自分の次の配置は、その時点で残った候補から組み合わせの評価が高い場所へ置く。
平均評価75%と最も悪いモデルの評価25%を合わせ、特定の相手の置き方への依存を抑える。

配置の評価は、自分の産出量、資源構成、数字のカバー範囲、港を使った建設速度、
道路の先の空き地、相手の最良の産出構成を比較する。初期配置の道も同じ予測で比較する。
将来の自分の配置は近似方策で、全員の全配置手順を完全探索するものではない。

## 港・資源の計算

`economy.rs` は都市・開拓地・発展カードに必要な資源の不足を、産出と銀行/港の交換で
埋めるまでの時間を見積もる。交換レートは**渡す資源**に適用する。
1つの余剰資源のプールで不足を補い、同じ余剰を別々の資源のために二重計上しない。
これは連続量の産出近似で、正確な資源獲得の待ち時間や交換の可否の証明ではない。
実際の探索の遷移・勝利判定はゲームエンジンの合法手と整数の資源で行う。

## 相手の立場からの評価

`strategy.rs` は各席について、その席の推定手札・産出・港・道路から次の建設機会を評価する。
道路は0/1最短距離で、既存の自分の道と、新設が必要な道を区別する。
相手の道と建物を通過できないこと、残りの駒、開拓地の距離ルールを反映する。
3本道路までの候補から、自分と相手のどちらが先に目標地点へ届きそうかを比較する。

終盤では、道・開拓地・都市・騎士・盗賊を指した後の公開盤面でも既存の勝利到達計算を行い、
相手の次手番の勝利可能性がどれだけ増減するかを評価へ戻す。
開拓地の唯一の勝ち場所の封鎖、都市の最後の麦を産出する場所への盗賊を戦術テストで確認する。
この到達計算には、最長路の将来を本数で近似する等、既存 ReachSolver の制約が残る。

## 発展カードと都市の比較

ゲームに設定されたカード構成（騎士14、勝利点5、進歩カード各2）と、公開された使用履歴、
自分の手札、推定された相手の伏せ札から残りの山を推定する。
購入では各種類が出る確率を残り枚数で計算し、連続購入では山を減らして再計算する。
都市を建てる手も同じ手順探索で評価するため、固定の「都市が常に優先」という規則ではない。

騎士の価値は、現在の最大騎士力の保持者、自分の使用済み騎士、手元の騎士、
今手番に買ったカードの使用制限を踏まえた進捗評価も加える。
これらの将来価値の重みは手作りであり、学習済みの最適価値関数ではない。

## 比較と再現

候補名:

- `v3`: 手順探索のみ（前段階で旧最高難易度v2より改善を確認）
- `v4_setup`: v3 + 初期配置
- `v4_strategy`: v3 + 相手目線の戦略評価と盤面変化の勝利ハザード
- `v4`: 初期配置と戦略評価の両方

```powershell
Set-Location C:\catan_lab
cargo test --workspace --profile bench-debug
cargo build --release -p catan-cli
.\target\release\catan.exe match v4 v3 v3 v3 --games 96 --seed 9700000 --no-time-limit
```

開発用は各候補96局、同じseed・席順で比較。最初の24局は盤面変化のハザードを追加する前の
参考実験であり、最終版の勝率とは扱わない。`runs/` に生ログを保存。

## 保証範囲

観測を通した情報だけを使い、相手の本当の非公開手札や未来の出目は使わない。
期待値と相手モデルを使って良い手を探すCPUであり、常に最善手という証明はない。
4行動先の選択的探索、限られた初期配置モデル、近似的な相手の勝利到達判定を使う。
任意の全交渉案や全ゲーム木の探索、自己対戦による価値学習・均衡計算は行っていない。
`max_nodes` は実時間の締切ではないので、判断時間は測定値で記載する。

全計算条件を含める。新規計算とキャッシュ計算の完全一致テストを追加した。
