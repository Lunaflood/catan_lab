# 観測契約（M0）: 人間に見えているもの ＝ CPU v2 に渡すもの

2026-09-07 に `crates/catan-wasm/src/lib.rs`（`state_json` / `note`）、`web/app.js`、`crates/catan-server/src/rooms.rs` を直接読んで棚卸しした。

## プロファイル `legacy_app`（既存 UI を維持する移行中の固定値）

| 情報 | 人間の画面 | CPU v2 への投影 | 根拠 |
|---|---|---|---|
| 盤面・港・盗賊の位置・建物・道 | 公開 | 公開 | `state_json` の `buildings`/`roads`/`robber` |
| 公開勝利点・最長路・最大騎士力 | 公開 | 公開 | `publicVp`, `longestRoad`, `playedKnights` |
| 相手の資源手札の**枚数** | 公開 | 公開 | `handSize` |
| 相手の資源手札の**中身** | 非公開（`hand: null`） | 非公開。推定（Belief）のみ | `state_json` は人間席か決着後だけ中身を出す |
| 相手の発展カードの**枚数**・**使用済み種類** | 公開 | 公開 | `devCount`, `playedKnights`（進歩カードは使用時に公開） |
| 相手の発展カードの**種類**・伏せた勝利点 | 非公開 | 非公開。購入世代＋不使用履歴から推定 | `dev: null`, `vp: null` |
| 自分の資源・発展・今手番に買った札 | 本人だけ | 本人だけ（`OwnState`） | |
| 発展購入の**時刻と枚数** | 公開（ログ「発展カードを買った」） | 公開イベント `BuyDev{card: None}`。内部カード ID は無い | `note()` |
| サイコロ・各人の産出 | 公開（ログ「収穫」に各人の内訳） | 公開 `Roll{produced}` | `note()` の Roll 分岐 |
| 建設・銀行交換・成立した交易の内容 | 公開 | 公開 | |
| 提案・対案・承諾・拒否 | 公開（個人ログ） | 公開 | オンラインでもサーバが全行動を配る |

| 7 の廃棄の内訳 | **公開**（ログ「木2 羊1 を捨てた」） | 公開 `Discard{bundle: Some}` | `note()` の Discard 分岐が `bundle_text` を出す |
| 盗みの資源種類 | ログ文は伏せる。**しかし `last.stolen` を全席に配り、アニメで札の絵が飛ぶ = 第三者にも漏れていた** | **当事者（奪った人・奪われた人）だけ**。第三者は「1 枚移った」だけ | M0 で UI 側を修正: 第三者には `stolen:"HIDDEN"`（裏向きの札が飛ぶ） |

| 銀行の資源別残数 | **公開**（`bank` を常時表示） | 公開（`bank_exact = true`） | `state_json` の `bank` |
| 山の発展カードの残枚数 | 公開 | 公開（種類は非公開） | |
| 実 RNG・出目 seed・山の並び・他席の観測履歴 | 非公開 | 非公開。推論 RNG は席ごとの定数から作る | |

**銀行について**: このアプリでは銀行が正確に公開され、廃棄の内訳も公開なので、「銀行差分から廃棄を推測する」問題は起きない（推測する必要がない）。
将来 `discard_public=false` のプロファイルを作るなら、銀行も潜在変数にし `19 − 実銀行 − 自分の札` を使わないこと（設計書 3.1）。

## 境界

- 本番 `Game` と実 RNG を持つのは Engine（`catan-core::game`）だけ。
- `catan-core::observer` が席ごとの `Observation` / `ObservedEvent` に投影する（信頼境界）。
- `catan-ai::agent_v2` は `Observation` / `ObservedEvent` しか受け取らない。`View` → `Observation` の変換は `View::observe()` が行い、v2 は `&Game` を受ける関数を持たない。
- `Observation.public.game` は「秘密を消した局面」（相手の手札・発展・今手番購入の内訳・山の内訳・RNG を 0/定数に置換）。同じ観測履歴を生む本番状態同士では bit 単位で一致する（テスト `fairness_v2`）。
- 相手の手番中も `observe()` は届く（ハーネス・WASM・サーバの 3 ホストとも、行動の適用直後に全席分を配る）。
- 順序番号 `seq` で重複適用を防ぐ。

## 脅威モデル（区別する）

1. **CPU の公平性**: ローカル/サーバの CPU が秘密を使わないこと。本書と `fairness_v2` テストが対象。
2. **オンラインの対不正性**: 悪意あるクライアントが秘密を解析できないこと。**現状は満たしていない**（サーバは seed と全行動を配り、各端末が完全状態を再現する）。v2 の範囲外。段階移行するなら「席ごとの観測を配るサーバ権威方式」が必要（設計書 3.2）。
