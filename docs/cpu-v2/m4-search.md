## 実装した探索（`crates/catan-ai/src/search_v2/mod.rs`）

自分の手番の 2 手読みの葉（自分の手番が終わった局面）から、**自分の次の手番が始まるまで**相手の手番をロールアウトし、静的評価と混ぜる。

- 相手方策 `OpponentPolicy` は**その相手自身の手札と公開情報だけ**を読む手続き方策（都市→開拓地→収穫/交換で建つなら→発展→騎士力→街道→道→終了。盗賊は相手の産出を止める。相手どうしの交易・独占はしない）。根の秘密・他人の手札・山の内訳は読まない → 全知化を作りで避ける。
- 根の候補はサンプル全体で 1 つ、ロールアウトは自分の次の手番で止める → 将来の自分がサンプルの秘密で手を変える場面を作らない（strategy fusion の主要な経路を塞ぐ）。ただし木の内側で情報集合を単位にした再サンプルはしていない（root sampling 型の近似。ISMCTS ではない）。
- 出目は推論 RNG で 1 本サンプル（期待値ではない）。

## 結果（第 2 ラウンド・480 局・seed 1700000・対照 v2_control×3）

| 版 | 勝率 |
|---|---:|
| v2（ロールアウトなし） | 31.9% ± 2.1 |
| ロールアウト 0.5 混合・1 本 | 27.1% ± 2.0 |
| ロールアウト 1.0（静的評価なし）・1 本 | 21.5% ± 1.9 |

**有害**。理由の候補: (1) 出目 1 本サンプルの分散が葉の値を汚す（候補間の差 数十〜数百点に対し、産出 1 回の評価差は数百点）、(2) 手続き方策が対照 CPU の実際の振る舞いと違う（学習していない相手モデル）、(3) 自分の手番の残り（廃棄・盗賊）を簡略化。判断時間は約 5 倍。

## 採否と残件

- 製品には入れない（`rollout_mix = 0` が既定）。`v2_roll` / `v2_roll1` / `v2_roll2` は実験版として残す。
- 改善するなら: 出目を期待値で畳む（11 通り × 相手 3 人は高価。主要な出目だけ）、相手方策を対照 CPU の 1 手読みにする（相手自身の視点で再推定が要る）、木の中で情報集合を単位にする（ISMCTS）。いずれも「確実に勝率が上がる」とは言えない（設計書 16）。
- 候補生成の拡張（progressive widening、任意の枚数の束）は未着手。現行の生成器（180 通りの提案）は「ルール上の全合法手」ではない（設計書 9）。
