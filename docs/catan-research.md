一次資料: 公式ルールブック&アルマナック(5th ed. 2020, Catan Studio) / 査読論文3本 / 最強OSS実装 catanatron のソースコード

## 0. 結論サマリ

### 0.1 CPUが弱い構造的な理由（実測に裏付けられたもの）

| # | 原因 | 根拠 |
|---|---|---|
| 1 | **初期配置が弱い** | 配置ロジックだけを改良し他は同一のエージェント同士で、勝率 15.2% vs 28.3%。配置だけで勝率が2倍近く動く（Guhe & Lascarides 2014） |
| 2 | **交易(プレイヤー間トレード)を実装していない/雑** | 世界最強OSS botの catanatron は行動空間に `OFFER_TRADE` を**生成すらしていない**（銀行/港の海上交易のみ）。Szita et al. も「実装が面倒なので交易は無効化」と明記 |
| 3 | **探索深度不足で「道ばかり作る」** | MCTSは開拓地(4資源必要=3〜4巡待ち)の価値を見通せず、目先の道に資源を溶かす（Szita et al. 2010 が人間に負けた原因として特定） |
| 4 | **ビルドプランの優先順位が固定** | JSettlersの `都市 ≻ 開拓地 ≻ 最大騎士力 ≻ 最長路 ≻ 発展カード` という固定順序を、状況依存のランキング関数に置換しただけで勝率 23.4% → 29.9% |
| 5 | **脅威評価がない** | colonist.io のbotは「リーダーが1〜2VPで勝つ状況でもリーダーと交易する」「常にリーダーから盗むので隠しVPがバレる」と実ユーザーから批判 |
| 6 | **多人数の扱いが2人ゲームの延長** | 3人以上ではmax^n / paranoid / BRS の選択が本質的。単純な自己最大化はキングメイキングを起こす |
| 7 | **隠れ情報の推論をしない** | 相手の手札・発展カードは不可視。カードカウンティングをしないbotは弱いし、「読み合いの気配」がなく人間として面白くない |

### 0.2 「面白さ」の所在

カタンの面白さの重心は**盤面最適化ではなく、交渉と妨害の対人ゲーム**にある。
- 競技勢が挙げる最重要スキルは「Board Awareness（誰が脅威か・あと何手で勝つか・何を止めれば勝てないか）」、次点が「Decision Making」、3位が「Table Presence（劣勢なら場を均し、優勢なら崩す弁論）」
- 「ロバーは置く場所より**置くぞという脅し**の方が価値が高いことがある」
- 「7VP以上のプレイヤーとは交易しない」という暗黙の同盟が競技の基本

→ **CPUを強く・面白くしたいなら、盤面評価より先に「交易AI」と「脅威評価」に投資すべき**。ここは先行研究がほぼ手つかずの領域でもある。

## 1. ルール完全仕様（実装精度）

### 1.1 盤面トポロジー

```
陸地ヘクス     : 19
頂点(交差点)   : 54   ← 開拓地/都市
辺(道)         : 72   ← 道
港             : 9    (3:1汎用×4, 2:1特化×5 = 木/土/羊/麦/鉄 各1)
数字チップ      : 18   (2〜12、7なし。2と12は各1枚、他は各2枚)
```
（catanatron `models/map.py`: `NUM_NODES=54, NUM_EDGES=72, NUM_TILES=19`）

地形とその産出:
| 地形 | 資源 | 枚数 |
|---|---|---|
| 森 Forest | 木材 Lumber | 4 |
| 丘陵 Hills | 土 Brick | 3 |
| 牧草地 Pasture | 羊毛 Wool | 4 |
| 畑 Fields | 小麦 Grain | 4 |
| 山地 Mountains | 鉄鉱 Ore | 3 |
| 砂漠 Desert | なし | 1 |

**土(3枚)と鉄(3枚)が構造的に希少** ← 道・開拓地の両方に土が要るので土が最大のボトルネック。

### 1.2 コンポーネント正確数（5th ed.）

- 資源カード **95枚**（各19枚 × 5種）
- 発展カード **25枚** = 騎士14 + 進歩6（街道建設2 / 収穫2 / 独占2）+ 勝利点5
- プレイヤー駒（各色）: 開拓地5 / 都市4 / 道15
- 特別カード: 最長交易路 / 最大騎士力

> 注: 「資源カード120枚(各24)」と書く資料があるが、それは5-6人拡張込みなどの数。基本セットは95枚。**銀行枯渇ルールがあるので枚数は実装に効く**（1.5参照）。

### 1.3 セットアップ

**ランダム配置（上級者向け）**
1. 枠を組む。地形19枚をシャッフルして配置
2. 港9枚をランダムに枠上へ
3. 数字チップ: 盤の角から反時計回りに渦巻き状に、裏のアルファベット順(A→R)で置く。砂漠はスキップ
   - 完全ランダムにする場合、**赤数字(6と8)が隣接してはいけない**（隣接したら入れ替える）

**初期配置フェーズ（2ラウンド・スネークドラフト）**
1. ラウンド1: 開始プレイヤーから時計回りに「開拓地1+隣接する道1」
2. ラウンド2: **最後の人から反時計回り**に2軒目。開始プレイヤーが最後
3. **2軒目に隣接するヘクスの資源のみ**を初期資源として受け取る
4. 2軒目を置き終えた開始プレイヤーからゲーム開始
- 距離ルールは初期配置にも適用
- 2軒目は1軒目と繋がっていなくてよい

### 1.4 ターン構造

```
1. ダイスロール（全員に影響）
2. 交易（国内交易 / 海上交易）
3. 建設・発展カード購入
```
- 発展カードは**自分のターン中いつでも1枚**プレイ可（**ダイスを振る前でも可**）
- 上級者ルール: 交易と建設のフェーズ分離を撤廃し、任意の順で交互に行ってよい（**その手番に建てた港をその手番で使える**）
- 手番終了後、左隣へ

### 1.5 生産と銀行枯渇（実装で落としやすい）

- 開拓地 → 1枚 / 都市 → 2枚（隣接ヘクスごと）
- ロバーのいるヘクスは産出しない
- **銀行枯渇ルール**:
  - ある資源が全員分に足りない → **その資源は誰も受け取らない**（そのターン）
  - ただし**影響を受けるのが1人だけなら**、その人は残っている分だけ受け取る（端数は消滅）
  - 他資源の産出は影響を受けない

### 1.6 「7」とロバー

1. **8枚以上**持っている全プレイヤーが半分（端数切り捨て）を捨てる。例: 9枚→4枚捨て、11枚→5枚捨て
2. ロバーを**必ず別のヘクス**へ移動（砂漠も可、同じ場所に留まるのは不可）
3. 移動先に隣接する開拓地/都市を持つ相手から**ランダムに1枚**盗む。複数いれば選べる。相手が0枚なら何も得ない
- 他プレイヤーに手札**枚数**を聞けば、正直に答える義務がある（=公開情報）

### 1.7 建設コストと上限

| 建造物 | コスト | 上限 | VP |
|---|---|---|---|
| 道 | 木1 + 土1 | 15 | 0 |
| 開拓地 | 木1 + 土1 + 羊1 + 麦1 | 5 | 1 |
| 都市 | 麦2 + 鉄3 | 4 | 2 |
| 発展カード | 羊1 + 麦1 + 鉄1 | 山札25枚 | (VPカードなら1) |

- 道: 自分の道/開拓地/都市に接続必須。1辺に1本
- 開拓地: **距離ルール**（隣接3頂点すべてが空であること。自分の建物でもダメ）+ 自分の道に接続必須
- 都市: 既存の自分の開拓地のアップグレードのみ。開拓地駒は手元に戻る（=5軒使い切っても都市化すれば再利用可）
- 発展カード山切れ後は購入不可

### 1.8 発展カード細則

| 種類 | 枚数 | 効果 |
|---|---|---|
| 騎士 Knight | 14 | 即座にロバー移動+盗む。場に表向きで残る |
| 街道建設 Road Building | 2 | 道2本を無料設置（通常の建設ルールに従う） |
| 収穫 Year of Plenty | 2 | 銀行から任意の資源2枚（同種2枚も可）。同一手番で建設に使える |
| 独占 Monopoly | 2 | 資源1種を指定、全員の手札から全て奪う |
| 勝利点 VP | 5 | 1VP。伏せたまま保持 |

- **買ったターンにはプレイできない**（VPカードは例外）
- 1手番に1枚まで
- **交易・譲渡は不可**
- 進歩カードはプレイ後ゲームから除外
- VPカードは**10点に到達して勝利宣言する時にのみ公開**。何枚でも同時に、購入したターンでも公開可

### 1.9 交易

**国内交易（プレイヤー間）**
- **手番プレイヤーが必ず当事者**。手番外プレイヤー同士の交易は不可
- 回数無制限、枚数任意
- **禁止**: 一方的な譲渡 / 同種資源の交換（鉄3↔鉄1など） / 発展カードの交易

**海上交易（銀行）**
- 4:1（港不要、常時可）
- 3:1 汎用港（同種3枚→任意1枚）
- 2:1 特化港（その資源限定。**他の資源は3:1にすらならず4:1のまま**）
- 手番中のみ。他人の手番には銀行と交易できない

### 1.10 最長交易路 / 最大騎士力

**最長交易路（2VP）**
- 5本以上の連続した道。**分岐は数えず、最長の1本の枝のみ**
- より長い道を作った者が即座に奪う（**4点スイング**）
- **相手の開拓地を道の途中の空き頂点に建てると分断できる**
- 同点処理:
  - 保持者が分断されても**同点なら保持したまま**
  - 保持者が最長でなくなり、かつ2人以上が新最長で同点 → **カードは脇に置かれる**（誰も持たない）。5本以上の道を持つ者が1人になった時に復帰
  - 5本以上が誰もいなくなった場合も同様

**最大騎士力（2VP）**
- 騎士カードを**3枚プレイした最初の者**
- より多くプレイした者が即座に奪う（同数では奪えない）

### 1.11 勝利条件

- **自分の手番に10VP以上**で即勝利
- 他人の手番中に10VPになっても、**自分の手番まで待つ**
- 内訳: 開拓地1 / 都市2 / 最長路2 / 最大騎士力2 / VPカード1
- 各プレイヤーは開始時点で2VP（=残り8VP）

### 1.12 実装で事故りやすいエッジケース チェックリスト

- [ ] 銀行枯渇時「全員なし」vs「1人だけなら残りを配る」の分岐
- [ ] 最長路の同点で「カードが宙に浮く」状態
- [ ] 最長路の分断判定（グラフの最長単純路、分岐を数えない）
- [ ] 最長路は**相手の建物で切れるが、自分の建物では切れない**
- [ ] ロバーは同じヘクスに置き直せない
- [ ] 発展カードをダイスロール前にプレイできる
- [ ] 買ったターンにプレイ不可（VPカードのみ例外）
- [ ] 収穫(Year of Plenty)で得た資源をその手番で使える
- [ ] 独占で銀行ではなく**プレイヤーから**奪う
- [ ] 開拓地5軒使い切り → 都市化しないと6軒目が建たない
- [ ] 距離ルールは自分の建物にも適用
- [ ] 初期配置2巡目の順序が逆回り、資源は2軒目のみ
- [ ] 廃棄は8枚以上、切り捨て
- [ ] 手札枚数の質問には正直に答える義務（=枚数は公開情報）
- [ ] 港は「その手番に建てても即使える」（上級者ルール）
- [ ] 3人プレイでも駒数・カード数は同じ

## 2. 確率と数理構造

### 2.1 ダイス目分布（2d6）

| 出目 | 通り | 確率 | pip |
|---|---|---|---|
| 2, 12 | 1 | 2.78% | 1 |
| 3, 11 | 2 | 5.56% | 2 |
| 4, 10 | 3 | 8.33% | 3 |
| 5, 9 | 4 | 11.11% | 4 |
| 6, 8 | 5 | 13.89% | 5 |
| 7 | 6 | 16.67% | — |

1 pip = 2.778% ＝ catanatron の `proba_point = 2.778/100` そのもの。

### 2.2 頂点の評価

- **pip合計**が第一次近似（隣接3ヘクスのpipの和、最大は理論上15）
- 競技での初期配置のpip合計は12→15+へインフレ
- 「勝つ初期配置は必ず6か8を含む」
- 期待産出量 = Σ(pip_i × 2.778% × 建物倍率)

**pip合計だけでは足りない補正**（Guhe & Lascaridesが実装して勝率を上げた要素）:
1. **同じ数字のヘクスを重複して取るのを嫌う**（産出が分散する方が、毎ターン何かが入る確率が上がり、7での廃棄リスクも下がる）
2. **2軒を同じヘクスに置くのを強く嫌う**
3. **資源種の多様性に重み**（catanatron は「新しい資源1種 = 産出4pip相当」と換算: `TRANSLATE_VARIETY = 4`）
4. 建造物ごとに必要資源の重みを変える（少ない資源で建つものを優遇）

### 2.3 資源需給

4種の建造物のコストを合計すると:
- 木: 道1 + 開拓地1 = 2
- 土: 道1 + 開拓地1 = 2
- 羊: 開拓地1 + 発展1 = 2
- 麦: 開拓地1 + 都市2 + 発展1 = 4
- 鉄: 都市3 + 発展1 = 4

だが**供給ヘクス数**は 木4/土3/羊4/麦4/鉄3。
→ **土は「需要2・供給3」で最も詰まる**。競技勢のボトルネック評価は 土 > 木 > 麦 > 鉄 > 羊。
→ 終盤の勝ち筋は 麦+鉄（都市と発展カード）。「序盤は土と木、終盤は麦と鉄」は公式アルマナックの Tactics 項にも明記。

### 2.4 ゲーム長（性能設計の基準）

- 4人戦: **1ゲーム約60〜80ロール**、オンライン実測で平均**71手番**（1人あたり17〜18手番）
- 平均獲得資源: 全体64枚 / 勝者76枚（**勝者は約12枚多い**、複数データセットで一貫）
- 理論上の最速勝利は4人戦で6.34手番、最遅は18.14手番

→ **1ゲーム = 数百アクション程度**。MCTSのプレイアウトは十分現実的だが、10,000シミュレーション/手 × 71手番 = 71万プレイアウト/ゲーム。エンジン速度が全て。

### 2.5 勝者のVP構成（実験勢24戦のデータ）

- 開拓地+都市で **6〜8点** が91.6%
- **勝者は全員、最長路か最大騎士力のどちらかを持っていた**（最長路のみ62.5% / 最大騎士力のみ45.8% / 両方8.3%）
- 発展カードを1枚以上買った勝者 87.5%（平均3.6枚）、うち58.4%がVPカードの恩恵
- 都市なしで勝ったのは1人だけ（開拓地5+最長路+最大騎士力+VP1）

→ **「都市+特別カードの片方」が標準的な勝ち筋**。AIの目標関数はここを反映すべき。

### 2.6 座席順の効果（見落とされがち）

Szita et al. の実測（各400戦）:
- **ランダムプレイヤー**同士では**1番手が有利**（単純に1手多く打てるため）
- **MCTSプレイヤー**同士では**1番手が最も不利、2・3番手が有利**

→ 戦略性が上がると座席の有利不利が反転する。**AI同士の評価実験では座席順をランダム化しないとバイアスが乗る**。

### 2.7 運と実力

- 勝者のダイス運の中央値は +0.071、それ以外は −0.058 → **勝者は平均して運が良い**
- 26戦程度では実力差が統計的に出ない。1戦45分なのでサンプルが貯まらない
→ **AIの強さを測るには数千〜1万戦の自動対戦が必須**（Guhe & Lascarides は1条件10,000戦。p<0.01で有意になるのは勝率24%未満/26%超）

## 3. ゲーム性の本質 —— 何が面白さを生んでいるか

### 3.1 交渉が主戦場

- 公式アルマナックの Tactics: 「**交易すればするほど勝率が上がる。自分の手番でなくても現手番プレイヤーに交易を持ちかけるべき**」
- ただし競技環境では**1ゲームあたりの交易回数が2008年の22回から2024年の6〜9回まで減少**している（=交易が「する/しない」の判断ゲームになった）
- 「自分が絡まない交易は全て他人を助けている」
- **7VP以上のプレイヤーとは交易しない**（劣勢側の暗黙の同盟）

### 3.2 ロバーの戦略（競技の4原則）

1. リーダーの最良ヘクスを止める
2. 手札が最も多い相手から盗む
3. **自分の産出ヘクスには置かない**
4. どうせ廃棄する時は自分をブロックする手もある

アンチパターン（人間もbotもやる）:
- 最下位を叩く（「罰する」本能）→ ほぼ勝敗を変えず、リーダーに使えたレバレッジを1回捨てている
- 常にリーダーから盗む → **隠しVPの情報を相手に与える**
- **脅しとしてのロバー**: 置く場所より「置くぞ」という交渉材料としての価値が上回る場面がある

### 3.3 妨害

- 相手の道の途中に開拓地を建てて最長路を分断（4点スイング）
- 相手の拡張先の頂点を先に押さえる（距離ルールで広範囲を封鎖できる）
- **道で相手を封じ込める**（公式アルマナックも「囲まれることに注意」と警告）

### 3.4 キングメイキング問題

3人以上のゲーム固有の問題。自分が勝てない状況で、誰を勝たせるかの選択が発生する。
- 単純な自己最大化AI（max^n）はこれを扱えない
- 全員が自分を狙うと仮定する paranoid はα-β枝刈りが効き**20〜50%深く読める**が、非現実的な仮定
- **Best Reply Search (BRS)**: 「最も自分にダメージを与える相手1人だけが動く」と仮定する緩和版
- MCTS + max^n が総合的に最良という報告もある
→ **設計上の選択が必要な論点。カタンで実測した文献はまだ薄い＝差別化の余地**

## 4. AI研究の全体像（実測値つき）

### 4.1 JSettlers (Thomas 2003) —— 全ての基準線

オープンソースJava実装。ほぼ全てのオンラインカタンAIの祖先。
中核概念:
- **ETB (Estimated Time to Build)**: ある場所にある駒を建てるまでの推定ターン数（ダイス・港・銀行交易を考慮）
- **ETW (Estimated Time to Win)**: 10VPまでの推定ターン数
- **BBP (Best Build Plan)**: 最善の建設計画列
- ビルドプランは5種: 開拓地 / 都市 / 発展カード / 最長路 / 最大騎士力（**「道」単体のプランは無い**）

手番の処理順:
1. イベント処理（ロバー配置、廃棄）
2. 合法かつ有望な建設地の列挙
3. 各候補の ETB と ES (Estimated Speedup) を計算
4. BBP を決定
5. BBPを実行（交渉・交易を含む）

2つのモード:
- **fast**: 次の1駒のETB最小化のみ
- **smart**: 10VPまでのプラン列を組んでETW最小化。**計算コスト約30倍**

### 4.2 Guhe & Lascarides 2014 —— 最も実務的な知見

各条件10,000戦。1体の改造エージェント vs 3体のベースライン（帰無仮説=勝率25%）。

| 改造 | 勝率 | 備考 |
|---|---|---|
| 素のjsettlers vs 改良初期配置×3 | **15.2%** | 初期配置だけで壊滅 |
| benchmark（初期配置のみ改良） | 28.3% | ヘクスからの資源獲得が15%増 |
| ranking（固定優先順位を廃止、ETBのみで比較） | **29.9%** | 対benchmark |
| favDC（さらに発展カードを係数−5で冷遇） | **29.3%** / 対jsettlersで**43.0%** | 最強 |
| smart（ETW全探索、30倍遅い） | 33.8% vs fast / **19.6% vs ranking** | **重い探索が軽いrankingに負ける** |

**教訓**:
1. **初期配置が単独で最大の効き目**
2. **固定優先順位（デフォルト選好）は害**。文脈依存の評価関数に置き換えるだけで勝率が上がる
3. **重い先読みが必ずしも勝たない**。rankingは30分の1のコストでsmartに勝った
4. 勝率とヘクスからの資源獲得量に有意な相関（r=0.207, p<0.05）
5. **交易プロトコルの設計が勝敗に効く**: 「最初にYESと言った人と取引成立」だと速いbotが得をする。「全員の返答を待ってから相手を選ぶ」に変えると結果が変わる
6. 人間の棋譜(38戦)との比較: 人間は道0.49 / 開拓地0.17 / 都市0.10 / 発展カード0.25 の比率で建てる。最強のfavDCが最も人間に近かった

### 4.3 Szita, Chaslot, Spronck 2010 —— MCTSの初適用

- 高速エンジン SmartSettlers を自作（**ランダムプレイで300ゲーム/秒**）。JSettlersのネットワーク経由では1ゲーム10分で全く足りなかった
- ルールを簡略化: 隠れ情報を除去、**プレイヤー間交易を無効化**
- 結果（対JSettlers 3体、各100戦。互角なら25%）:
  - ランダム: **0%**（ほぼ1点も取れない）
  - MCTS 1,000シミュレーション/手: **27%**（JSettlersと互角）
  - MCTS 10,000シミュレーション/手: **49%**（明確に上回る）
- **人間の上級者には確実に負けた**

**ドメイン知識の注入で分かったこと**:
- プレイアウトの行動重み付け（開拓地/都市に+10,000など）を入れたら**逆に弱くなった**。建設を急ぎすぎて道による布石を軽視したため
- 一方、**探索木側への virtual win 注入は明確に有効**（開拓地建設に20勝、都市に10勝を初期値として与える）
- **重要な罠**: virtual win を親ノードへ逆伝播させてはいけない。「開拓地を建てられる状態」が「実際に建てる」より高く評価されてしまう

### 4.4 catanatron (bcollazo, 現行最強OSS)

数千ゲーム/秒で回るPython実装。リーダーボード（1v1、n=25）:

| Bot | 勝率 | 対戦相手 |
|---|---|---|
| **AlphaBeta(n=2)** | 80% | ValueFunction |
| ValueFunction | 90% | GreedyPlayouts(n=25) |
| GreedyPlayouts(n=25) | 100% | MCTS(n=100) |
| MCTS(n=100) | 60% | WeightedRandom |
| WeightedRandom | 60% | Random |

→ **深さ2のalpha-beta + 手作り評価関数が、MCTSより強い**。カタンは分岐と偶然性が大きく、浅い探索＋良い評価関数の方が費用対効果が高い。

#### 評価関数（実際にチューニングされた重み）

```
public_vps            : 3e14      ← 勝ちは何よりも優先
production            : 1e8       ← 自分の期待産出
enemy_production      : -1e8      ← 相手の期待産出（同じ重みで負）
reachable_production_1: 1e4       ← 道1本で届く産出
buildable_nodes       : 1e3       ← 建設可能な頂点数（＝拡張余地）
hand_synergy          : 1e2       ← 手札が「次の建設」にどれだけ近いか
army_size             : 10.1
longest_road          : 10        ← ただし建設可能頂点が0の時のみ有効化、通常は0.1
hand_devs             : 10
num_tiles             : 1         ← 接している異なるヘクス数
hand_resources        : 1
discard_penalty       : -5        ← 8枚以上持っている時
```

**設計上の要点**:
- 「産出」は期待pip値 + **多様性ボーナス**（`資源1種 = 4pip相当`）
- `hand_synergy` = 都市までの距離と開拓地までの距離から算出する「手札の噛み合い度」
- **最長路の重みが動的**: 拡張余地が残っている間はほぼ無視（0.1）、詰まった時だけ本気で狙う（10）
- 相手の産出を自分と同じ重みで減点している = **妨害が明示的に評価に入っている**

#### 行動空間の設計（そのまま流用できる）

```
ActionPrompt: BUILD_INITIAL_SETTLEMENT / BUILD_INITIAL_ROAD / PLAY_TURN
              / DISCARD / MOVE_ROBBER / DECIDE_TRADE / DECIDE_ACCEPTEES
ActionType  : ROLL, MOVE_ROBBER(coord, victim), DISCARD,
              BUILD_ROAD(edge), BUILD_SETTLEMENT(node), BUILD_CITY(node),
              BUY_DEVELOPMENT_CARD,
              PLAY_KNIGHT_CARD, PLAY_YEAR_OF_PLENTY(r,r), PLAY_MONOPOLY(r), PLAY_ROAD_BUILDING,
              MARITIME_TRADE(5-tuple),
              OFFER_TRADE / ACCEPT_TRADE / REJECT_TRADE / CONFIRM_TRADE / CANCEL_TRADE,
              END_TURN
```
- 「ロバーを(0,0,0)に動かして青から盗む」という**意図**を1アクションで表現し、結果（実際に盗めたカード）は `ActionRecord.result` に分離 → **リプレイ・巻き戻し・学習用データ生成が全部これで回る**。最初からこの設計にしておくべき

#### 偶然性の扱い（expectimax）

`execute_spectrum(game, action)` が `[(次の状態, 確率), ...]` を返す:
- `ROLL` → 2〜12の11分岐、各々2d6の確率
- `BUY_DEVELOPMENT_CARD` → 山札 + 相手の伏せカードを合わせた「自分視点で有り得る山」から確率計算
- `MOVE_ROBBER`(盗む相手あり) → 5資源を各1/5（※本来は相手の手札構成で重み付けすべき近似）
- 独占は「カードカウンティング完璧・銀行可視」と割り切って決定的扱い

#### 枝刈り

- 初期配置で**1ヘクスしか接していない頂点を除外**
- 3:1港を持っているなら4:1交易を候補から除外
- **ロバー**: 相手の産出ヘクスのうち「(相手産出 − 自分産出)を最大化する1手」だけを残す（他は全部捨てる）
- friendly robber オプション: VP3未満の相手をブロックする手を除外（=最下位いじめ防止）

#### 決定的な発見: **catanatron は国内交易(OFFER_TRADE)を生成していない**

`generate_playable_actions` の `PLAY_TURN` 分岐に入っているのは `MARITIME_TRADE` のみ。
`DECIDE_TRADE` / `DECIDE_ACCEPTEES` のプロンプト処理は実装されているが、**offerを作るコードがどのbotにも無い**。
→ **世界最強のOSSカタンbotは「交渉なしカタン」を遊んでいる**。ここが完全な空白地帯。

### 4.5 深層学習・LLM系

- **PPO/自己対戦 (henrycharlesworth)**: カスタム環境 + PPO + 学習済みエージェントを使った forward search。作者評「良い人間には及ばないが、対戦相手としては楽しい程度」
- **HexMachina (2026, arXiv 2506.04651)**: LLMエージェントがcatanatron上で自己進化。1v1で **54.1%**（VP 8.2）で AlphaBeta（51.0%、VP 7.8）を上回った。Reflexion型の素のLLMは16.4%、ランダムは0.2%
  - 進化した最強プレイヤーが獲得した振る舞い: **フェーズ依存の優先度**（序盤=拡張 / 中盤=バランス / 終盤=都市化）、**産出多様性**、**ロバーによる妨害の明示的ヒューリスティック**、2手先の浅いロールアウト
  - 失敗した構成: 「現在VPをほぼそのまま評価値にする1手読み」→ ロバーの使い方も配置も壊滅
- **Pfeiffer 2004 (RL) / Hanna et al. 2010**: 共通の結論として **「RLもMCTSも、事前に相当量の記号的ヒューリスティックとドメイン特化の構造がないと機能しない」**

### 4.6 交易AIの先行研究

- 人間の交易データからの学習で、Bayesian Network / CRF / Random Forest を比較 → **Random Forest がオファーのランキングで最良**
- 交渉では「相手の資源選好を分析し、オファー前に対話で情報収集する」ことが有効
- Guhe & Lascarides は STAC コーパス（人間の対戦38戦＋対話注釈）を使用。信念・記憶の欠落が交渉に与える影響、説得の効果も研究している
- **LLMを交渉に使う際の既知の落とし穴**: 言語モデルは「会話の一貫性」を最優先し、**機械的な真実を回避して友好的に振る舞ってしまう** → 外部のルール検証層が必須

## 5. 自作するなら —— 設計上の示唆

### 5.1 アーキテクチャ

```
[ ルールエンジン (高速・純粋・決定的) ]
      ├─ 状態は「配列の塊」に近い形で持つ（コピーが安い＝探索が回る）
      ├─ Action / ActionRecord 分離（意図 と 結果）
      ├─ 完全な undo / replay
      └─ 数千ゲーム/秒 が最低ライン
[ 行動生成 (合法手列挙 + 枝刈り) ]
[ AI層 (差し替え可能) ]
      ├─ 評価関数 (重みは外部データ)
      ├─ 探索 (expectimax + alpha-beta 深さ2 が現時点の最良コスパ)
      ├─ 交易モジュール ★ 空白地帯
      └─ 対戦相手モデル (カードカウンティング)
[ 自動対戦ハーネス ] ← 1条件10,000戦、座席順ランダム化
[ UI ]
```

**エンジンとAIを最初から分離すること**。Szita も Guhe も「既存実装のネットワーク越しでは遅すぎて研究にならない」と同じ壁にぶつかっている。

### 5.2 強いAIを作る順序（費用対効果順）

1. **初期配置の評価関数**（最大の効き目。pip合計 + 数字分散 + 資源多様性 + 拡張余地 + 港）
2. **状況依存のビルドプラン選択**（固定優先順位を作らない）
3. **相手産出の減点項**（妨害を評価に組み込む）＋ ロバーの1手最良化
4. **深さ2の expectimax + alpha-beta**（MCTSより先にこれ）
5. **交易AI** ← ここで既存実装を全部抜ける
6. カードカウンティング / 隠しVP推定
7. 多人数探索の方式選択（max^n / paranoid / BRS）

### 5.3 「面白さ」のために意識的に設計すべきこと

強さ ≠ 面白さ。友人と遊ぶ用途なら以下が効く:

- **難易度の段階**: 探索深さ・評価関数の重み・交易の寛容さ・妨害の強さを別々のノブにする
- **性格（パーソナリティ）**: 「木土型」「麦鉄型」「発展カード型」「妨害型」「交渉好き」など。プレイスタイルの違いは**評価関数の重みベクトルを変えるだけで作れる**（catanatronの重みが良い出発点）
- **交渉の可視化**: botが「なぜ断ったか」を一言返す（「リーダーとは取引しない」等）だけで対人感が跳ね上がる
- **「7VP以上とは交易しない」等のメタ規範を実装** → 人間側にも同じ圧力がかかり、ゲームが締まる
- **キングメイキングの扱いを明示的に決める**（勝てない時に何を最大化するのか）
- **最下位いじめを避ける**（catanatronの `friendly_robber` 相当）。強さは落ちるが体験は上がる
- **盤面バランス生成**: 赤数字非隣接 + 資源の偏り抑制 + 3本の対称軸での分布評価。「バランス盤」「荒れ盤」を選べるようにする

### 5.4 評価実験の作法（先行研究の失敗から）

- **1条件10,000戦**。26戦では実力差は出ない
- **座席順をランダム化**（座席バイアスは有意、しかも戦略の強さで符号が反転する）
- 勝率だけでなく **ヘクスからの資源獲得数 / 交易で得た資源数 / 建てた駒の種類比率** を記録（どこが効いているかが分かる）
- 人間の棋譜と比率を比較する（L1距離）。**人間らしさと強さは相関した**（favDCが最強かつ最も人間に近い）

## 6. 未確定・自分で決める必要がある論点

1. **交易AIの設計**（先行研究が薄い。オファー生成の行動空間をどう有限化するか、受諾判断をどうするか）
2. **多人数(3-4人)での探索方式**（max^n / paranoid / BRS のカタンでの比較データが無い）
3. **隠れ情報の推論**（相手の手札の確率分布を保持するか、determinization で済ませるか）
4. **廃棄(DISCARD)の行動空間**（catanatron は組合せ爆発を避けて「何を捨てるか」を行動から外している＝ここは改善余地）
5. **独占・収穫の最適タイミング**（データ解析の余地あり）
