# catan_lab

カタン（基本セット・3〜4人）の自作実装。目的は **強くて面白い CPU**。

調査レポート: [docs/catan-research.md](docs/catan-research.md)

## 構成

```
crates/
  catan-core/   ルールエンジン。外部依存ゼロ・決定的・ヒープ確保なし
  catan-ai/     評価関数・交易AI・枝刈り・探索・評価ハーネス
  catan-cli/    自動対戦・速度測定・重みの ablation と掃引
  catan-wasm/   ブラウザとの橋渡し（C ABI + JSON）
web/            SVG の盤面。素の HTML/CSS/JS のみ
```

## 使い方

```bash
cargo test --workspace
```

```bash
sh build-web.sh && python serve.py
# → http://localhost:8787
```

```bash
cargo run --release -p catan-cli -- match greedy placement placement placement --games 10000
cargo run --release -p catan-cli -- eval-ablate 2400
cargo run --release -p catan-cli -- eval-sweep buildable_nodes 80,160,320 2400
```

## 強さ（2026-09-07 時点）

すべて席の全順列を巡回、1 条件 4,000 戦以上。帰無仮説は 25.0%。

| 対戦 | 勝率 |
|---|---|
| **GreedyEval vs Placement×3** | **97.3〜97.5%** ± 0.3 |
| **GreedyEval vs GreedyEval-narrow×3**（提案の枚数制限だけが違う） | **45.6%** ± 0.8 |
| GreedyEval vs GreedyEval-v1×3 | 89.0% ± 0.6 |
| Placement vs WeightedRandom×3 | 78.0% ± 0.7 |
| WeightedRandom vs Random×3 | 95.5% ± 0.3 |
| VpGreedy vs Random×3 | 0.0% |
| Search(d=2 / 3 / 4) vs GreedyEval×3 | 25.3% / 25.5% / 24.8%（**効果なし**） |

完成版の同型 4 体: 24.6〜25.3%（席バイアスなし）・**膠着 0%**・平均 **82.4 手番**。
Placement を相手にした時は **63.6 手番** で、人間の 4 人戦の実測値 71 手番と近い。

## 完成版 CPU の中身

**1 手読み + 評価関数 + 交易AI + 枝刈り**。先読みはしない（後述）。

- **初期配置**: 専用の評価関数（総 pip と資源の種類）
- **評価関数**: 勝利点／自分と相手の期待産出（盗賊込み）／拡張余地／手札の「力」／
  相手の手札の充実度 × 脅威度／最大騎士力／最長路（拡張余地が尽きた時だけ重くする）
- **交易**: 提案・対案・承諾・相手選びを、成立後の局面の差分で評価。
  **相手が受けるかどうかを、相手の立場で同じ評価関数を回して判定する**
- **枝刈り**: 盗賊・海上交易・提案を安い物差しで並べて上位だけ完全評価
- **視界**: 資源の手札は見える／発展カードの種類と伏せた勝利点は見えない。
  先読みは `View::determinize()` で未知の札を引き直した局面の上で行う

規範は書き込んでいない。「リーダーと交易しない」「リーダーのヘクスを止める」
「自分のヘクスに盗賊を置かない」は、評価関数の項（相手の産出・手札を勝利点で重み付け）から出てくる。

## 測定して分かったこと

### 1. 評価関数に「即時の勝利点」だけを置くと必ず壊れる（2 回踏んだ）

- **VpGreedy（1 手先の VP だけ）は勝率 0.0%**。道は即時 VP を生まないので 1 本も建てず、
  初期 2 軒から拡張できない。VpGreedy 同士は 300 戦すべて未決着
- **同じ病が桁を変えて再発した**。VP の重みを 1000 にした最初の評価関数（v1）は、
  4 体で回すと **37% の対局が膠着**した。全員が初期 2 軒を都市に変え、拡張用の道を建てず、
  発展カードの山も尽きて誰も 10 点に届かない（実測で 19,498 手番の対局が出た）

治し方は VP を下げることではなかった。**拡張余地の重みを上げること**:

| 重み | 変更 | 結果 |
|---|---|---|
| `buildable_nodes` | 3 → 200 | 勝率 23.8% → **85.7%** / 膠着 35% → **0%** |
| `expansion_now` | 40 → 600 | 膠着 35% → 1% |
| `vp` | 200〜2500 | **どこでも変わらない**（支配的でありさえすれば大きさに意味は無い） |

`buildable_nodes` は 640 まで上げると 61.8% に崩れる（拡張先を消費する開拓地を建てなくなる）。

### 2. 交易は「成立後」を作らないと評価すらできない

`OfferTrade` を指しても資源は動かない（相手の返答を待つだけ）。素直に 1 手読むと
評価値が 1 ミリも変わらず、**ボットは絶対に交易しない**。これが catanatron が
交易を行動空間から外している理由でもある。成立後の局面を先に作って比べると **+39.6pt**。

**そして枚数を 1 種類に縛ると CPU が目に見えて弱くなる。**
公式ルールに枚数の制限は無い（禁じられているのは同種を両側に置くことだけ）。
にもかかわらず自動生成を「1 種類 ↔ 1 種類」に留めていたので、
「木 1 と土 1 を出して鉄 1 が欲しい」という、実戦で最も要る形が作れていなかった。

複数種類の束（`2 種類 → 1 種類` と `1 種類 → 2 種類`）を生成に足して、
**同じ盤・同じ規則の下で、そこを見るか見ないかだけを変えて**測った:

| | 勝率 |
|---|---|
| GreedyEval（複数種類の束も考える） | **45.6%** / 別 seed **44.2%** |
| GreedyEval-narrow ×3（1 種類どうしだけ） | 17.5〜18.9% / 17.5〜20.0% |

**+20pt 以上**。z = +26.2。ルールの側を狭めていたわけではない（`apply` は最初から
任意の合法提案を受ける）。狭かったのは **AI が探す範囲** だった。
「規則としては許されているが生成していない手」は、探索の外にあるので永久に指されない。

そして相手モデルが要る。「払えるか」だけで相手を選ぶと、相手も賢い場合はことごとく断られ、
手番を提案で溶かす（**同型 4 体で 18% の対局が終わらなくなった**）。

さらに、連続量（手札の噛み合い）だけで測ると微差の 1:1 交換が常にわずかに正に見え、
**1 試合で 1,163 回交易して対局が終わらない**。「実際に何かが払えるようになるか」という
離散の段差を積むと 14.8 回/試合に収まった（競技の人間は 6〜9 回）。

### 3. 先読みは効かない

手番内の expectimax を深さ 2 / 3 / 4 で回しても、1 手読みと**同じ 25% 前後**。
コストは 3 倍 / 8 倍 / 17 倍。

Guhe & Lascarides 2014 が「ETW を全部読む smart は 30 倍重くて、軽い ranking に
19.6% vs 26.8% で負ける」と報告したのと同じ結果。カタンでは
**良い評価関数 × 浅い探索**が費用対効果で勝つ（catanatron のリーダーボードも同じ順序）。

深く読むと、評価関数の誤差をより強く最適化してしまう。効く投資は探索深度ではなく評価関数の側。

### 4. 手で決めた重みは、ほとんどが無駄か有害

初期配置の 10 項目のうち、ablation を通ったのは 2 項目だけだった（各条件 10,000 戦）。

| 項目 | 寄与 |
|---|---|
| pip（総産出） | **+10.1pt** |
| variety_new（新資源1種） | **+7.9pt** |
| expansion / etb×3 / port×2 | ±0.3pt（有意差なし） |
| same_hex | **−0.6pt**（入れると弱い） |
| number_dup | **−1.0pt**（入れると弱い） |

`port_specific` は明確に有害（6 で 73.5%）。「初期配置で港を追うのは罠」という定説を実測で再現。

評価関数側も同じで、`afford_road` は 0 が最適（0.6 で 20.8%、0 で 27.3%）。
道が払えることを手札の「力」に数えると判断が濁る。

### 5. 結論は「その時の相手」の下でしか成立しない

初期配置の 2 項目版は、下流が WeightedRandom の時に決めたもの。
下流を完成版に差し替えて測り直したら、2,400 戦では 10 項目版が **+3.0pt** で勝った。
ところが 6,000 戦・別 seed では **+0.8pt（z=+1.4、有意でない）**。**再現しなかった**。

差が小さい時ほど、掃引に使っていない seed での再検証が要る。単純な 2 項目版を維持している。

### 6. 計器そのものの欠陥を 2 つ潰した

- **席のローテーションでは足りない**。各ボットが全部の席に座っても「誰の次に座るか」が
  固定され、強いボットの直後の席だけ不利になる（同型のはずの 3 体が 11.8 / 14.4 / 17.9%）。
  **全順列を巡回**させると 15.0 / 14.5 / 15.2% に揃った
- **手番数の上限が要る**。カタンには本物の膠着があり、1 局が測定時間の大半を食う

### 8. 手の一覧は「作った時刻」の状態でしかない

ブラウザで対局中に **エンジンが panic して止まった**。

`legal_actions` は交渉が開いている前提で提案を並べる。その後 UI が実時間を流し込んで
持ち時間が切れると、並べたはずの提案は `apply` に弾かれる（`assert!(negotiation_was_open)`）。
UI 側は一覧を作り直していなかったので、切れた後に古い提案をそのまま指していた。

```
legal_actions()  → 提案が 120 通り並ぶ
tick(500) ×N     → 交渉の持ち時間が切れる
apply(その提案)  → panic
```

直し方は 2 か所: **時計が交渉を閉じた瞬間に一覧を作り直す**のと、
**ボットが指す直前に必ず作り直す**（前の手からここまでに時計が進んでいる）。

★ 一般化すると **「合法手の一覧は、作った時刻の状態でしかない」**。
時間で変わる規則があるなら、一覧を持ち回してはいけない。

### 7. その他

- **Random は交渉つきの行動空間では基準線にならない**。1 試合で提案 1,298・対案 3,421 を
  出して溶かす。catanatron が交易を外している理由でもある
- **catanatron の最長路計算には欠陥がある**。相手の建物がある頂点へ入る辺を丸ごと除外していて、
  「相手の集落で終わる 5 本の道」が 4 本になる。本実装は公式解釈（入れるが先へ進めない）
- **席順バイアスは実在する**。ランダム同士を席固定で回すと 1 番手が有利（Szita et al. 2010 と一致）
- エンジンは **465 万行動/秒**。交渉・対案を足しても落ちていない

## 実装済みのルール

初期配置（スネーク順・2 軒目のみ資源）／生産と**銀行枯渇ルール**／7 と廃棄と盗賊／
建設と駒数上限／発展カード 25 枚（買ったターンは使用不可・1 手番 1 枚・勝利点カードは例外）／
海上交易 4:1・3:1・2:1／**国内交易（提案・対案・全員の返答を待ってから相手を選ぶ）**／
**手番の持ち時間（既定 2 分・設定可。切れると交渉だけ止まる）**／最長交易路（同点処理込み）／
最大騎士力／勝利判定（自分の手番のみ）

### 意図的な単純化

- 対案は 1 往復まで。多段の値切りは「対案を見て提案し直す」形で表現（持ち時間が上限）
- `legal_actions` が自動生成する提案は 120 通り（単一資源の 1:1・2:1・1:2 と、2 種類↔1 種類の束）。
  3 枚以上や 3 種類の束は生成しないが、`apply` は任意の合法提案を受けるので UI からは指せる
- 発展カードの山はシャッフル済みの列ではなく残枚数（統計的に等価・複製が無料）
- 初心者用の固定マップ未実装

## Web UI

ブラウザで遊べる。**wasm-bindgen も wasm-pack も npm も使っていない** ── エンジンが外部依存
ゼロなので、そこをブラウザ側まで通した。`cargo build --target wasm32-unknown-unknown` が
吐いた 287KB の .wasm を、素の `WebAssembly.instantiate` で読むだけ。

やり取りは 2 つだけ:
- Rust → JS: 盤面と局面を JSON で書き出す（書く方向だけなので手書きの 100 行）
- JS → Rust: **合法手を番号で返す**（Rust 側に JSON パーサが要らない）

盤面の座標も Rust 側で出している。立方体座標のまま
`px = (√3/2)·s·(x−y)`, `py = 1.5·s·z` で中心が出て、**頂点は「共有する 3 ヘクスの中心の平均」**、
辺は両端の中点。海のヘクスも同じ格子上にあるので港の位置も同じ式で出る。
隣接表を手書きしていないのと同じ理由で、ここも書き間違いようがない。

できること: 初期配置のクリック配置 / サイコロ / 盗賊（ヘクス→相手の 2 段階）/ 建設 /
交易の提案・対案・諾否 / 棋譜 / CPU 同士の観戦。
提案は 1 手番に数十通り並ぶので折りたたんである。

### 見た目

**ボードゲームの再現はしていない**。木の枠・布のテクスチャといった「卓上の物」の意匠は捨てて、
明るい海の一枚画の上に情報を置くデジタルな画面にしてある。画像ファイルは 1 枚も無く、全部 SVG。

- **一面の海**。海は SVG の中では描かない。SVG は縦横比を保って収まるので、そこに塗ると
  「収まった矩形」の縁が見えてしまう。海は**ページの地（CSS）にだけ**置き、盤も欄もその上に浮かべる。
  盤の入れ物には背景も枠も持たせない
- **地形**は森＝針葉樹、丘陵＝煉瓦と丘、牧草地＝羊、畑＝麦穂、山地＝雪を被った峰、砂漠＝砂丘とサボテン
- **港は船**。木の船体・帆・旗が沖に浮かび、桟橋が陸まで伸びる。
  **2:1 の港は帆と札の縁がその資源の色**になるので、遠目でも何の港か分かる
- **開拓地は家**（屋根瓦・扉・灯りの入った窓・煙突）、**都市は城**（胸壁つきの二つの塔・旗・門）
- **街道は敷板**。太い線ではなく、枕木を並べた板として描く

港の沖への出し方は決め打ちしていない。陸ヘクスの中心から海ヘクスの中心までを 1 として
`PORT_OFFSHORE = 0.97`（当初 0.62 で船が陸に被った）。
**「港の絵がどのヘクスにも被らない」ことと「陸と港が全部描画範囲に入る」ことをテストが実測する**ので、
数字をいじって壊れたら落ちる。描画範囲は外接六角形から逆算せず、
**中身（陸の頂点＋港の絵）の実際の広がり**から出している。

### 演出

CSS の transform を SVG の上に重ねている。エンジンは `LastAction`（種別・誰が・どのヘクス・
どの頂点・誰から・何を盗んだか）を吐くだけで、絵の都合は一切知らない。

- **サイコロ**: 盤の中央に大きく落ちてくる。上から現れて 2 度跳ね、転がっている間は
  48ms ごとに目が入れ替わる（0.65 秒）。止まると合計が下に出る。
  中央だけ暗幕を掛けて、盤の数字チップと目が混ざらないようにしてある
- **街道**: **自分の拠点がある側の端から敷き伸びる**。どちらの端から伸ばすかは
  「自分の建物がある端 → 自分の既存の道がつながっている端」の順で探して決める
  （中央から膨らませると、どちらから来た道なのか分からない）
- **盗賊**: 前のヘクスから新しいヘクスへ滑って移動。盗んだ相手の**実際の建物**から
  カードが飛んでくる（`victim_building()` が被害者の建物を引く）
- **騎士**: 盗賊が押しのけられて跳ねる
- **建設**: 手前の集落から人が出てきて建て、砂ぼこりが立つ

### 画面

**ページ自体はスクロールしない**。中の欄がそれぞれ自分でスクロールする。

- **手札と操作は盤の右下**、プレイヤー欄のとなりに浮かせてある。
  右の欄に積むとプレイヤー欄を押し出してしまう
- **手番のはじめは「サイコロを振る」と「発展カードを使う」の 2 つだけ**。振ったあとは
  **できること全部を並べる** ── 街道・開拓地・都市・発展カード・発展を使う・銀行と交換・交易を提案・手番終了。
  **できない手も消さずに残し**、要る資源をカードの絵で出して足りない物だけ赤く落とす
  （理由の全文はマウスを乗せると出る）。
  できる手とできない手は**色・地・枠の 3 つを同時に変えて**分ける（できない手は灰色・地なし・破線）
- **取り返しのつかない手には必ず確認を挟む**。発展カードを買う・使う、銀行との交換、盗賊を置く場所は、
  選択肢が 1 つしか無くても 1 画面挟む
- 建てる物を選んでから盤面が光る。全部を一度に光らせるとどれがどの手か分からない
- **交易は最初から最後まで絵で見せる。文字は使わない**
  - 提案: 上段が欲しい物、下段が出す物（手札の枚数が上限）。
    同じ資源を両側に置くとその側は自動で 0 に戻る（ただで貰う形になるため）
  - 提案された側: **いきなり対案の画面**が開き、**提案された条件が入った状態**から始まる
    （相手が欲しい物＝こちらが出す物、として読み替えて入れる。払えない分は手札まで落とす）。
    枚数を**変えなければ「このまま受ける」、変えれば対案**になる。
    別画面で選ばせると対案が白紙から始まって、元の条件との関係が切れてしまう。
    貰う側は**相手が提示していない資源でも選べる**（「羊をくれるなら土を出す」が言える）
  - **提案が全員に断られたら、手の一覧ではなく提案の画面へ戻る**（条件を作り直す場面なので）
  - 提案してきた人の色でその欄を塗る（プレイヤー欄と同じ色づかい）
  - 対案は **「候補として積む」→「対案を返す」の 1 本道**。積むまで返せない。
    積んだ後の欄は**空に戻す**（元の条件に戻すと、次の候補を「−」で削るところから始めることになる）。
    条件を作る操作と返答を確定する操作を混ぜると、作りかけの条件が入るのか入らないのかが分からなくなる
  - **対案には「or」が置ける**。「木か土ならいいよ」は 1 本の条件では書けないので、
    成立してよい条件を並べて（`MAX_COUNTER_ALTS` = 4 本まで）**提案者に選ばせる**。
    候補は `CounterAlt` で積み、最後の `CounterOffer` でまとめて 1 回の返答になる。
    積んだ候補は**中身が絵で並び、`✕` で取り消せる**（`CounterAltRemove`。消すと後ろが前へ詰まる）
  - **出す側は、手札に無い資源が落ちて見える**（灰色＋薄く）。持っていない物を数えようとして
    「なぜ増えないのか」を探させない
  - 提案した側: 全員の返答が「受けた / 対案 / 断った」で並び、
    **対案は中身が絵で出る**。誰と成立させるかをそこから選ぶ

盤の中央でサイコロが転がるのは **`last.kind === "ROLL"` の時だけ**。
「手番と手番プレイヤー」を鍵にしていた頃は、交渉中に返答のたび `to_act` が変わるので
**提案するたびにサイコロが降ってきた**。
- **右上に「できごと」**。**直近 5 巡ぶん**を残してスクロールで遡れる
  （数行で切ると「さっきの流れ」が読めず、全部だと長い対局で重くなる）。
  誰が何をしたかを 1 行ずつ、プレイヤー色つきで。
  **払った資源と得た資源をカードの絵で添える**（赤が −、緑が +）。
  サイコロの後は誰が何を収穫したかも並ぶ。
  **記録するのはカードが動いた出来事だけ**。「提案した」「断った」といった交渉の往復は
  過程であって盤面には何も起きていないので、詳細ログにも出さない
- **盗む相手は持ち物つきのカードで選ぶ**。相手 **全員** の勝利点・手札・発展・騎士・最長の道を並べ、
  奪えない相手は落として理由を書く（「このヘクスに面していない」「手札が無い」）。
  **どのヘクスを押しても必ず確認を挟む** ── 面しているのが 1 人でも、誰も居なくても
  （押した瞬間に確定すると押し間違いが戻せない）
- **発展カードは 1 枚しか持っていなくても種類を選ぶ画面を挟む**。
  「気づいたら騎士を切っていた」は取り返しがつかない。銀行との交換も同じ
- 画面から字を削ってある: 手番の見出し（誰が何をしたかは棋譜で分かる）／手札の枚数（カードに書いてある）／
  押せる時の注釈。残すのは **押せない理由** と、**今すぐ効く情報**（交渉の残り時間・7 で捨てる警告）だけ
- **「詳しく」で詳細ログが「できごと」のすぐ左隣に開く**。高さは「できごと」と同じ、幅はそれより広い。
  **4 人を縦に区切って横へ並べ**、スクロールするのは各列の中身だけ（誰かを見るために全体を動かさない）。
  **1 巡ぶんだけ**を出し、`◀ ▶` で前後の巡へ移る。既定は最新で、対局が進めば付いていく。
  手札と操作の欄には重ならない（操作欄が高い時は高さを詰め、それでも足りなければ操作欄の左へ回る）
- **銀行・港との交換**も提案と同じ枚数の決め方。出す側は**レートの倍数**でしか動かず
  （4:1 の資源なら 4 枚ずつ）、貰う側は出した回数ぶんだけ選べる。
  **8 枚出して 2 枚貰う**のを 1 回の操作でできる（`MaritimeTrade` は 1 回 1 枚なので、
  中では普通の海上交易を続けて指しているだけ。ルールは変えていない）
- **交易・廃棄・銀行との交換を組んでいる間、手札は「成立後の枚数」を出す**（増えるカードは緑、減るカードは赤の縁）。
  「これを出したら何が残るのか」を頭の中で引き算させない
- **7 の廃棄**も交易と同じカードで。**出す側だけ**を出して、何を捨てるか枚数で選ぶ
- **独占・収穫**は資源カードを並べて選ぶ。発展カードは先に**種類**（騎士・街道建設・収穫・独占）で選ばせる
- **盤の置き場所は操作の欄に合わせて動く**。普段は横の余白の半分だけ左に寄せて大きく使い、
  **交易の画面が開いて欄の背が高くなった時だけ**、その左に収まる大きさに縮む
  （右側の港が隠れないように）
- 欄の地は透かしてぼかすが、**ボタンには下地を敷く**。透かしたままだと字が読めない
- **手札はトランプ札のような縦長**（2:3）。真四角だとカードに見えない。
  持っている発展カードの内訳は「発展を使う」の横に出す（使う場所と同じところに置く）
- **決着したら結果を盤の上に出す**。誰が勝ったかだけでは「なぜ勝ったか」が分からないので、
  勝利点の内訳（開拓地・都市・最長交易路・最大騎士力・伏せていた勝利点）を
  **全員ぶん、点数の高い順に**並べる
- **上の帯は既定で畳んである**。題字も設定もボタンも出さず、盤が画面いっぱいに広がる。
  左上の小さな矢印だけが常に出ていて、押すと帯が降りてくる
- **「できごと」の左に銀行の欄**。5 種類の在庫といまの出目を出す
  （銀行が切れているかは交易の判断に直結するのに、今までどこにも出していなかった）
- **その対局の出目の分布**もその帯の中。棒がその目の回数、細い白線がその時点の**理論値**。
  「7 ばかり出る」と感じた時に、本当に偏っているのか、そう見えるだけなのかをその場で見分けられる
  （比べる相手を画面に置いておく）
- **プレイヤー欄**は手札・発展・騎士・最長路を絵と数字で、その下に**残りの駒数**（道・開拓地・都市）。
  自分の行にだけ、持っている**発展カードの内訳**も出す。
  各行は**その人の色で薄く塗る**。**手番の人はその色で脈打つように光り、他の行は落とす**。
  誰の行かを字ではなく面で分からせる。
  濃さは一番明るい色（白に近い P2）が手番の時でも文字とのコントラストが 4.85:1 を保つ値にしてある
- **席はランダム**。毎回 1 番手だと初手の有利不利が固定されてしまう
- **伏せた勝利点は本人にしか見えない**。自分の欄は本当の点、他人の欄は公開点に `+` を付けて出す。
  CPU も見えていない ── `View` は `public_vp` しか返さず、`Game` 本体は私有フィールド。
  テストは「相手の手札の発展カードを勝利点 2 枚 ↔ 騎士 2 枚に入れ替えても CPU の指し手が変わらない」
  ことを 40 局面で確かめる（アクセサの有無ではなく**挙動**で確かめる）
- **種は出来事ごとに別**（盤 / サイコロ / 発展カード / 盗み の 4 本）。
  1 本の流れを共有すると、誰かが発展カードを 1 枚多く引いただけで**以降のサイコロが丸ごとずれる**。
  分けてあるので「盤はそのまま、サイコロだけ振り直す」が効く。種は `crypto` から引く。

  ⚠ ただし **出目の質そのものは変わらない**。PCG32 は元から一様で、実測でも
  23,986 回の出目が理論値どおりに出ている（7 = 16.32% / 理論 16.67%、2 = 2.74% / 2.78%）。
  分離が効くのは「毎回ちがう試合になること」と「出来事どうしが絡まないこと」の 2 点。

盤の光だけに進行を預けない。**クリック待ちなのに光る場所が 1 つも無ければ、
手を一覧で出す保険**が入る（街道建設カードの無償の道が光らず、実際に進行不能になったことがある）。

資源の増減は行動ごとに書き分けていない。**手札の前後の差**から出しているので、
交易・海上交易・建設・産出のどれでも同じ 1 か所で正しくなる。


## 友達と対戦する（オンライン）

GitHub Pages に置いた版は **1 人用**（CPU との対戦）です。
友達と同じ盤を囲むには、あなたの PC でサーバを立てます。

### 手順

**1. `run-online.cmd` をダブルクリックする**

必要な物が無ければ自動で組み立てます（初回だけ数分）。
黒いウィンドウに、開くアドレスが出ます。

**2. 出てきたアドレスをブラウザで開く**

| 誰が遊ぶか | 開くアドレス |
|---|---|
| 自分 | `http://localhost:8788/` |
| 同じ家の Wi-Fi の友達 | `http://192.168.x.x:8788/`（ウィンドウに出ます） |
| 外にいる友達 | 下の「外の友達を呼ぶ」を参照 |

**3. 名前を入れて「友達と遊ぶ部屋を作る」を押す**

**友達に送るリンク**が出ます。「リンクをコピー」で写して、そのまま渡してください。

**4. 友達はそのリンクを開いて、名前を入れて「この部屋に参加する」**

合言葉を打ち込む必要はありません（リンクに入っています）。

**5. 全員そろったら「はじめる」**

空いた席は CPU が埋めます。強さは席ごとに選べます。

### 外の友達を呼ぶ

一度だけ、トンネルの道具を入れる:

```
winget install --id Cloudflare.cloudflared
```

以降は `run-online.cmd` を起動するだけ。画面にこう出る:

```
 ========================================================
   外の友達に渡すアドレス

     https://xxxx-xxxx-xxxx.trycloudflare.com

   ↑ まずこれを自分のブラウザで開いてから部屋を作ってください
 ========================================================
```

このアドレスは**起動のたびに変わる**（クリップボードにも入る）。
**必ずこのアドレスで開いてから部屋を作ること。**
`localhost` のまま作ると、コピーされるリンクも家の中でしか通じない
（その場合は画面に警告が出る）。

⚠ **あなたの PC を起動したままにする必要がある**。ウィンドウを閉じると対戦は終わる。

### 作りについて

**エンジンが決定的である**ことを使っている。同じ種と同じ手順を入れれば
どの端末でも必ず同じ盤になるので、サーバが配るのは
「何番目の手を指したか」だけで、盤は各自のブラウザが再現する。

サーバの仕事は 3 つだけ:

- 席を配る
- **手番でない人の手を撥ねる**（ここだけは端末を信用しない）
- CPU の手を決めて配る（各自が勝手に決めるとズレるため）
